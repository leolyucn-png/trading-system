# 🏹 赵云 V1.0 — 复盘归因引擎

> 2026-07-05 建立 | 版本：**V1.0**
> 定位：第11模型 · 每日收盘后自动运行 · 为曹操提供结构化输入

---

## 一、核心任务

```
收盘后15:05自动启动 → 梳理今天所有交易 → 归因分类 → 写出结构化报告
曹操15:20读取赵云报告 → 更新校准数据库
```

## 二、每日运行流程

### Step 1：采集今日数据（15:05）
```
① 读 memory/trades.md → 今日所有成交
② 读 memory/交易日志/YYYY-MM-DD.md → 今天操作记录
③ 读 SESSION-STATE.md → 今日预判执行情况
④ 通过akshare获取今日全A股收盘数据 → 验证盈亏
```

### Step 2：逐笔归因分类
```
每笔买入/卖出/持有都归入以下五类之一：

✅ 正确
  - 止盈卖出后继续涨（正常，不是卖飞）
  - 尾盘买入次日盈利（T+1正确）
  - 止损后继续跌（正确风控）

❌ 卖飞
  - 卖出后T+5涨幅 > +5%（真卖飞）
  - 卖出理由与催化无关（恐慌卖）
  - 案例：晶澳+10.5%、先导+3%、中国卫星+6.4%

❌ 踏空
  - 关羽给了信号但没有建仓，T+5板块涨幅 > +3%
  - 小乔说A/B级但最终没买，T+5个股涨幅 > +5%
  - 反事实对比：如果买了 vs 实际没买

❌ 止损
  - 亏损>-5%才止损（违反止损纪律）
  - 案例：完美世界-23%、天通-13%、楚江-11.9%

❌ 追高
  - 买入时个股已涨 > +3%（违反汉武帝规则）
  - 板块涨停潮当天买入（违反时序规则）
  - 案例：三星电气、三七互娱
```

### Step 3：日度指标计算
```
├── 已清仓胜率 = 盈利笔数 / 总交易笔数
├── 平均盈亏比 = 平均盈利 / 平均亏损
├── 超额收益 = (组合收益 - 同期大盘收益)
├── 卖飞率 = 卖出后继续涨>5%的笔数 / 总卖出笔数
├── 死扛率 = 浮亏>-5%未止损的持仓 / 总持仓
├── 纪律执行率 = 按铁律执行操作数 / 应执行操作数
└── 模型方向正确率 = 关羽方向正确次数 / 关羽总信号次数
```

### Step 4：输出结构化报告
```
写入 memory/赵云归因/YYYY-MM-DD.md

格式：
  - 今日总览（总盈亏/胜率/超额收益）
  - 逐笔归因表（每笔交易+分类+原因）
  - 反事实统计（卖了但涨的/信号但没买的）
  - 纪律审计（今天违反的规则清单）
  - 经验提取（今天新发现的模式）
  - 曹操输入数据包（结构化JSON给曹操读取）
```

---

## 三、周度/月度汇总

```
每周日：汇总本周所有赵云日报 → 周度归因报告
  - 本周模式统计（最常犯的错误类型）
  - 本周vs上周指标对比
  - 参数优化建议（如：止损线是否该从-5%调到-3%？）
  - 模型健康度评分（每个模型的准确率变化）

每月末：月度汇总 → 参数迭代提案
  - 如果连续2周某规则表现差 → 建议修改
  - 如果某模型连续2周方向错误率高 → 建议降权
```

---

## 四、铁律

```
1. 赵云不修改规则 → 只提建议，不自动改代码
2. 赵云不交易 → 纯分析，不买不卖
3. 归因必须具体 → 不能写"运气不好"，必须落到具体模型/规则/执行
4. 所有数据必须通过API验证 → 不凭记忆写盈亏数字
5. 报告必须有「曹操输入数据包」→ 统一格式供曹操直接解析
```
